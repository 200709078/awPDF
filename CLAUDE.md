# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

awPDF is a PDF viewer in the spirit of Adobe Reader (pdf.js, TypeScript + Vite) shipped as a web app, an Electron desktop app (Linux AppImage/deb, Windows NSIS) and an Android app (Capacitor, APK). More PDF tools will be added later. It is meant for class smart boards (Pardus ETAP) as well as phones and PCs. The UI, test names, docs (README, `docs/yol-haritasi.md`) and messages are in **Turkish** — keep new user-facing strings and docs in Turkish.

Status: the web app is live at `madematik.com/awPDF/` (deploy with `npm run deploy`) and packages are on GitHub Releases since 0.0.2. What is done and what remains is in `docs/yol-haritasi.md`; record new requests there with a date and do not implement any item until the user explicitly asks.

## Decisions (2026-11-02, the user's)

- **Stack:** the drAW family's: TypeScript + Vite, Electron, Capacitor. **Engine:** pdf.js (`pdfjs-dist`), its `PDFViewer` components with our own UI; never its ready-made `viewer.html`.
- **Platforms:** Linux, Windows, Android, and the web at `madematik.com/awPDF/`. iOS waits (it needs a Mac and a paid Apple account).
- **Repository:** own public repository `github.com/200709078/awPDF`, MIT. **App ID** `com.madematik.awpdf` is permanent (Play Store).
- **Release files:** `.github/workflows/release.yml` and `scripts/release-assets.mjs` stay byte-identical with drAW, drAW2D and drAW3D. Android uses the family's shared signing key.
- **Class smart boards from the start:** touch comes first (large targets), with an on-screen keyboard and a presentation mode.
- **Tabs:** tabs on the desktop and the web; a single document on Android (`Platform.singleDocument`).
- **Large files:** above 200 MB, on every platform, the user is warned and may still open the file (`core/open-policy.ts`). **Nothing is ever refused**, and there is no page limit: page count is known only after opening and says little about the load. Per-platform values may come later if tests call for them. The real protection is inside the app: partial reading, drawing only visible pages, on-demand cancellable search, a per-page pixel limit.
- **Dark theme** colours the interface only; PDF pages keep their own colours.
- **The first version never changes a PDF.** When editing tools come, the default is "Save as"; the original is never overwritten silently.
- **Local only:** a PDF never leaves the device and the app needs no network. No analytics, no remote fonts.
- **Goal limit:** editing a PDF's existing text like a word processor is not a goal.

## Architecture

- `src/main.ts` mounts the desktop title bar and calls `startApp`; `src/app/app.ts` is the composition root connecting the platform, the document view and the tools, and owns the open flow (large file warning, load, errors).
- **Platform layer** (`src/platform/`): `Platform` is everything that differs between Electron, Android and the web; the rest of the app talks only to it. `core/recent-files.ts` keeps the recent list and the page each document was left on, keyed by pdf.js's fingerprint, in `localStorage`; the way back to a file is the platform's `PdfFile.source` + `reopen`: a file handle in IndexedDB on Chromium, an opaque id on the desktop, a persisted content URI on Android (from its own picker). Without a source the user picks the file again. Files arrive through `onFile`, not as the picker's return value, because the system's "open with" and drag and drop deliver files too. `browser.ts` is the base; `desktop.ts` and `android.ts` override only what differs (full screen, print, share, opening links). All three use the browser's file picker and take dropped files where the system allows it; on Android and the desktop "open with" delivers files as well.
- **Partial reading** (`src/core/`): `PdfFile` (`name`, `size`, `read(begin, end)`) is how every platform hands over a file. `pdf-document.ts` feeds it to pdf.js through a `PDFDataRangeTransport` with `disableAutoFetch` and `disableStream`, so a file is never read whole (`tests/viewer-integration.spec.ts` "büyük dosya bütünüyle okunmaz" measures this). `enableXfa` is off and the viewer gets no scripting manager, so a PDF's own scripts never run.
- **pdf.js import order:** `pdf_viewer.mjs` reads `globalThis.pdfjsLib` while loading, so `core/pdfjs-global.ts` must be imported first. The **legacy** build is deliberate: it also runs in the older WebViews of school tablets. The version is pinned; read its changelog before bumping (6.x removed `PDFDocumentProxy.destroy` and `isEvalSupported`).
- **pdf.js assets:** `cmaps`, `iccs`, `standard_fonts`, `wasm` are copied from `node_modules` into `public/pdfjs/` by the plugin in `vite.config.ts` (gitignored) and so ship with every build. `public/.htaccess` gives `.mjs` a JavaScript type, without which the web host would break the worker.
- **Tools** (`src/tools/`): a `Tool` declares its label, icon, shortcuts, availability (`needsDocument`, `isAvailable`), an on/off state (`isActive`), platform support (`isSupported`), whether it has a button (`inToolbar`) and `run(context)`; `tools/index.ts` is the single list, and `ui/toolbar.ts` builds the buttons (ID `tool-<id>`) and the shortcuts from it. The row never scrolls: by width, not by device, the buttons that do not fit move from the last one back into the `#toolbarMenu` menu, the same elements, shown there with their names. While the menu is open its ☰ button is a ✕ ("Menüyü Kapat"). A new feature is a new file there, plus panels when they are needed; the core stays untouched. Tools reach the document and the platform only through `ToolContext`.
- `.document-area` has `isolation: isolate`: pdf.js gives each link and form field a rising z-index (64+ on a long contents page), which otherwise lay unseen over the toolbar menu, the narrow side panel and the presentation exit and took their taps (a tester's report, 2026-11-04; `toolbar.spec.ts` "belgedeki bağlantılar…").
- `src/app/document-view.ts`: wraps `PDFViewer`, `EventBus` and `PDFLinkService`. pdf.js draws only visible pages and keeps its own per-page pixel limit (lower on phones), so we set none. Fit-width and fit-height are reapplied when the container resizes; a zoom the user chose is kept. Two-page view pairs 1-2, 3-4 (`SpreadMode.ODD`); pdf.js resets it with each document, so `pagesinit` reapplies the choice. Outside links go through `ConfirmingLinkService` → `confirmExternalLink`, showing the whole address; only `core/links.ts` protocols leave the app, checked again in `electron/main.ts`. Search matches are yellow, the current one orange with a darker edge (`app.css`, the user's testers' choice); blue would look like a selection. Search uses `TurkishFindController`: pdf.js's `match` receives text folded by `core/turkish-search.ts` (same length, so positions hold), because case-insensitive regexes do not know I/ı and İ/i. Closing the search detaches the finder (after a microtask, or `findbarclose` never clears the highlights), which stops its page-by-page reading.
- `src/app/document-tabs.ts`: the open documents. All stay loaded; there is one `DocumentView`, and a tab keeps its `ViewState` (page, scale, rotation) while another is on screen. `DocumentView` no longer owns a document: `DocumentTabs` destroys it and closes its file. The same document (by fingerprint) is not opened twice. Files open one at a time, so dialogs do not stack.
- `src/ui/side-panel.ts` is the panel beside the document (a drawer over it below 700px, where a choice closes it); it starts closed and is toggled by the `sidePanel` tool. It slides in pure CSS (`@starting-style`, `transition-behavior: allow-discrete`) on the `hidden` attribute, so older browsers just skip the animation; `DocumentView` refits only after the size settles, so the slide does not redraw the page each frame. `src/ui/outline.ts` adds the document's table of contents as a tab, shown only when it has one. `src/ui/thumbnails.ts` fills the pages tab: pdf.js does not export its thumbnail viewer, so this is ours. Thumbnails are drawn one at a time through an `IntersectionObserver` and released when they leave the view margin, so a closed panel draws nothing and a long book stays cheap.
- `src/app/gestures.ts`: pinch and ctrl+wheel call `zoomAt` (`updateScale` with a `drawingDelay`, so a pinch stretches the page and redraws after it stops); in single page view a swipe or the wheel at the edge turns the page. With nothing to scroll sideways it cancels horizontal `touchmove`s, because otherwise Chromium takes them as the back gesture and leaves the app; `overscroll-behavior` does not help on a non-scrolling viewport.
- `src/app/presentation.ts`: one page at a time, full screen, with the bars hidden by CSS (`is-presenting`). A tap goes on, one in the left third goes back, and a button leaves; on leaving, the layout and zoom come back. Leaving full screen by the browser's own Esc ends it too.
- **On-screen keyboard:** `electron/screen-keyboard.ts` is drAW's service (ETA Klavye or Onboard over D-Bus, Linux only; `tests/screen-keyboard.spec.js` is its test). `src/ui/screen-keyboard.ts` asks for it while a text field has the focus, only on a board (`platform/smart-board.ts`, `?tahta=1` forces it); a phone's system sees to its own keyboard.
- `src/app/print.ts`: pdf.js does not export its print service. Pages become 150 DPI images in `#printContainer`, which the `@media print` styles show alone; the view's rotation does not apply, filled-in form fields do (`AnnotationMode.ENABLE_STORAGE`). `askPrintPages` asks first: all pages, this page or a range (`core/page-range.ts`). Android prints the WebView through `AwPdfNativePlugin`, and keeps the images until the next print, since the print service reads them later.
- **Saving** (2026-11-06): always a new file, never the open one (`Platform.saveFile`; `SameFileError` when the user picks a file that is open). Chromium's `showSaveFilePicker`, else a download; Electron `files:save` (its own dialog, refuses a path that is open, starts in the original's folder); Android `saveFile` (`ACTION_CREATE_DOCUMENT`, the data arrives first in pieces through `appendShareFile`, no permission). **Forms:** pdf.js's viewer already draws fields as inputs (`ENABLE_FORMS`); `saveAs` (ctrl+s) writes `saveDocument()`. pdf.js resets its "modified" flag as soon as it writes, so `saveTab` puts it back (`DocumentTabs.markUnsaved`) when the user cancels. `DocumentTabs` watches `annotationStorage.onSetModified/onResetModified`; `requestClose` and `mayReplace` ask through the close guard (`askUnsavedChanges`); `beforeunload` holds the page and Electron's `will-prevent-unload` shows the question. Toolbar letter shortcuts do not fire in inputs, textareas or selects.
- **Page editor** (`src/ui/page-editor.ts`, tool `editPages`): a full-screen `<dialog>` of page cards over a `core/page-plan.ts` plan (remove, rotate, move, append; nothing is written until saved). `core/pdf-build.ts` writes the result with pdf.js `extractPages` (also copies the open document's form values). pdf.js keeps the open document's password when only its pages are used and drops it when files are joined; an added encrypted file is copied without its password by joining a blank page (`blankPdf`), which is never used. `extractPages` cannot rotate, so `core/pdf-rotate.ts` appends an incremental update that rewrites each turned page object under its own number with a new `/Rotate` (numbers are not encrypted, so encrypted files stay valid). It parses only pdf.js's own fresh output (plain page objects) and throws otherwise. Cards are drawn near the view only, one at a time. The `cancel` event (Esc, and `back.ts`, which dispatches it on the last open dialog) asks before leaving with changes; the editor dialog comes first in `index.html` so dialogs opened over it are later in the page. The toast is a `popover` so it shows above open dialogs. `pdf-lib` is a dev dependency only, for the form test PDFs (`tests/helpers/make-form-pdf.mjs`).
- **Pictures** (2026-11-06): `core/images-to-pdf.ts` writes a PDF with one JPEG per page (`DCTDecode`, the file unchanged; A4 turns for a wide picture, or a page of the picture's own size at 96 DPI). `app/images.ts` `jpegFromFile` decodes with `createImageBitmap(..., { imageOrientation: 'from-image' })`, so a phone photo's EXIF turn is applied, paints transparency white and scales to at most 3508 px. `pdfFromImages` (tool `imagesToPdf`, `#emptyImages`, and an image dropped on the window via `openNow`) asks the page size and opens the result in the page editor with `isNew` (savable unchanged, asks on leaving, owns the document). The editor's add button takes pictures too. `app/page-images.ts` renders a page or a `PageRegion` (fractions of the page as shown) at a DPI with form values; `savePagesAsImages` saves one PNG/JPG or a `core/zip.ts` archive (stored, UTF-8 names). `ui/region-capture.ts` (tool `captureRegion`) lays `.region-overlay` over `.document-area` (above the PDF thanks to its isolation), takes a drag, renders the part at 300 DPI and offers save, copy (`ClipboardItem`) and share. Canvases are encoded with `toDataURL` (`canvasBytes`), never `toBlob`: an Android WebView holds `toBlob` back some four seconds per call (measured on a phone, 2026-11-06); printing uses it too. `Platform.saveFile` and `share` take a `FileType` (`PDF_TYPE`, `PNG_TYPE`, `JPEG_TYPE`, `ZIP_TYPE`); Electron accepts only those extensions, Android only those MIME types.
- **Marking** (2026-11-08, tool `annotate`, "İşaretle"): pdf.js's own editing layer (the `AnnotationEditorUIManager` every `PDFViewer` makes, mode NONE until used) with our bar `ui/annotate-bar.ts` under the toolbar: Kalem (INK), Fosforlu (HIGHLIGHT, pdf.js's colours `HIGHLIGHT_COLORS`), Metin (FREETEXT); colours and sizes, Geri Al / Yinele / Seçileni Sil, Bitti (or Esc, or back). `DocumentView` keeps pdf.js out of the bar: `setEditorMode` (resolves once pdf.js has switched and unselected; settings sent earlier would change the selected mark), `changeEditor` (`switchannotationeditorparams`), `undo`/`redo`/`deleteSelected` (`editingaction`), `onEditingChange` (`editingstateschanged`). pdf.js's own mode switches (`switchannotationeditormode`, e.g. tapping a mark of another kind) are followed only while the bar is open. **Pen strokes** gather into one drawing until the pen stops; until then they are not in the document's storage, so `finishEditing` (`uiManager.endCurrentEditing`) runs before saving, printing, the page editor, saving images, closing and switching tabs. The bar's buttons do not take the focus (`mousedown` default prevented): the layer losing it ends the drawing, and undo would take all strokes at once. The marks are annotations in `annotationStorage`: `saveDocument` writes them (name suffix "işaretli"), printing and page images draw them (`annotationStorage.print`), `extractPages` keeps them. **Tabs:** pdf.js makes a new editing manager per document and the old one's editors no longer show (they still save and print). `DocumentView` copies them while they are on the page (`copyMarks`) and, when a page's editing layer is drawn again (`annotationeditorlayerrendered`), makes them again as clones (`isClone`, so they are not moved aside like a paste; the text box's position is set back, pdf.js puts a copy a line higher), removes the old ones and keeps "unsaved" as it was. In ink or highlight mode a one-finger swipe does not turn the page (`gestures.ts`). The editing layer's words are Turkish: `GenericL10n('tr')` with `public/pdfjs-l10n/` (`locale.json`, our own `tr.ftl` with only the strings used), found through `<link rel="resource" type="application/l10n">`; a missing string shows pdf.js's English.
- **Signatures** (2026-11-08, the marking bar's İmza mode; no toolbar button of its own, the row is already full at 1440 px; with no kept signature the mode opens the dialog at once): pdf.js's signature editor (SIGNATURE), whose dialog is part of its full viewer, not of the components; ours is `ui/signature-dialog.ts` (Çiz on a pad, Yaz traced by `SignatureExtractor.extractContoursFromText` in a cursive font where the device has one, Görsel traced by `SignatureExtractor.process`). `core/signatures.ts`: `SignatureShape` (curves in a box, `areContours` for traced ones) and `SignatureStore` (localStorage `awpdf.imzalar`, at most 5, on this device only). `DocumentView.addSignature` puts one in the middle of the page in view (`CREATE` with `signatureData`); in signature mode a tap on a page puts the chosen one there (`signAtTap`, `createAndAddNewEditor`; a tap that only unselects does not), because pdf.js places one only in the middle. The `signatureManager` given to `PDFViewer` is a stub (pdf.js asks it only for an empty signature). Saved, a signature is a Stamp annotation with a vector appearance.
- **Word → PDF** (2026-11-07, tool `wordToPdf`, `#emptyWord`, a dropped `.docx`/`.doc` via `openNow`, the editor's add button): `app/word-to-pdf.ts` `wordToPdf` first asks `Platform.wordToPdf`: on the desktop `electron/office.ts` runs LibreOffice when it is installed (PATH, or Program Files on Windows; Pardus and the boards have it): `--headless --convert-to pdf` on a temporary copy with a fixed name, its own profile in userData (a LibreOffice the user has open does not take the job), one job at a time, 3-minute timeout, only `docx`/`doc`. The result is Word's layout with real text, and `.doc` works there; `hasOffice` adds `.doc` to the pickers. Elsewhere (web, Android), or if LibreOffice fails on a `.docx`, `wordPages` draws the pages itself: docx-preview (Apache 2.0, lazy-loaded chunk; `jszip` with it) lays the document out in an off-screen `.word-render` host, a `<section>` per page (where Word last broke, `lastRenderedPageBreak`), and each page is painted through an SVG `<foreignObject>` at 150 DPI, JPEG pages on `imagesToPdf(..., 'image')` with `JpegImage.dpi`; that text is a picture. `BASE_CSS` gives the host and the SVG the same starting styles (the app's border-box and font must not reach the document). A section a little longer than its page is shrunk up to `SHRINK_LIMIT`; a longer one (a document no Word paged) is paged by `flowedPages`: its single `<article>` gets a page's height and `column-fill: auto`, so the browser fills the columns in order and breaks lines itself, the overflow columns lie to the right and page k shows the k-th group (moved by a margin and clipped, not transformed, so positioned pictures keep their containing block); a section of several flows is cut under lines instead (`slices`). `core/word-fonts.ts`: missing fonts get a generic family (an unknown font would fall back to serif), Symbol/Wingdings text and Word's private-code-point bullets become ordinary characters (≤ ≥ ≠ π ☑ •), and docx-preview's unitless line heights are multiplied by 1.15 (Word's single line is the font's line height; measured against LibreOffice). Floating text boxes (wps) are not placed as in Word: docx-preview's limit, which is why the desktop uses LibreOffice. Embedded fonts are ignored. Tests write `.docx` files in memory with the `docx` dev dependency (`tests/helpers/make-docx.mjs`); `scripts/test-electron.mjs` checks the LibreOffice path when it is installed.
- `electron/main.ts`: shell only. Production loads `awpdf://app/` (a privileged custom scheme, served from `dist/` with a CSP), **not `file://` as the siblings do**: documents are untrusted, and this way a page can neither read the disk nor reach the network. `nodeIntegration: false`, `contextIsolation`, `sandbox`; navigation and new windows are denied. The window is frameless: `electron/preload.cts` (compiled to `dist-electron/preload.cjs`) exposes only `window.awPDFDesktop` (`windowControls`, `files`, `screenKeyboard`, `office`), and `src/ui/title-bar.ts` draws the bar only when that API exists. `electron/files.ts` reads files for the page, in parts, by number; the page never learns a path (`adopt` takes a real `File`, `reopen` an opaque `source` kept in `dosyalar.json`). One instance only: a second start hands its files over. `.pdf` is registered through `build.fileAssociations`.
- `android/`: the Capacitor 8 project, taken from drAW2D (committed; `android/app/src/main/assets/public` is generated by `cap sync`). `app/build.gradle` reads `versionName` from `package.json` and `versionCode = major·10000 + minor·100 + patch` (minor, patch < 100), and signs release builds from the `ANDROID_KEYSTORE*` environment. `MainActivity` fixes the WebView `textZoom` at 100. `AwPdfNativePlugin.java` prints, shares (the PDF is copied in chunks to the cache, then offered through `FileProvider`), hides the system bars, gives them the toolbar's colour (`Platform.setSystemBars`, laid on again after a turn of the phone) and takes the back button: `app/back.ts` closes the topmost thing on screen, then the document (back to the first screen), and only on the first screen does the app go behind the others. The `closeTab` tool ("Belgeyi Kapat", ctrl+w) is in the toolbar on every platform. `setSystemBars` sends colours as #RRGGBB: `Color.parseColor` does not read the #fff the build makes of #ffffff. `<input type=file>` is the picker. A PDF from "open with" (intent filters in the manifest) reaches `handleOnNewIntent`, which Capacitor also calls for the launch intent, and then the page through the retained `fileOpened` event; `readFile` serves ranges from its descriptor, so it too is read in parts, and a pipe (no size, no seeking) is copied to the cache first. The signing key never enters the repository. The app asks for **no permissions**, not even `INTERNET` (removed 2026-11-03, `tools:node="remove"` in the manifest so no library adds it back): pages come from Capacitor's local server and outside links open in the browser through an intent. Do not add a permission without the user; the privacy page and the Play listing say there are none.
- Icons: the source is `public/img/app-icon.svg` (the family style: a blue A and a red W, here on a page with a folded corner: a low, wide AW at the top left of the fold and a bold dark PDF below it, centred, both left-aligned; the user's design of 2026-11-03); `scripts/icons.sh` generates the rest.
- `app.css` sets `box-sizing: border-box` everywhere except inside `.pdfViewer`: pdf.js sizes its pages as `content-box`, and otherwise the drawing shrinks inside the page border while the text layer does not, so search highlights slide off the words.
- Stylesheets are linked from `index.html`, not imported in TS, so the first paint is styled. Vite `base: './'`.

## Releases

GitHub Releases is the only place packages are published. Same as the siblings:

- **Build:** `.github/workflows/release.yml` builds Linux on `ubuntu-latest`, Windows on `windows-latest` and the signed APK (secrets `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`; missing secrets fail the job, so nothing is published). Never cross-build Windows from Linux and never upload release assets by hand.
- **Version:** `package.json` is the single source. New release: `npm version patch`, then `git push --follow-tags`; ask the user first. The workflow fails if the tag differs from `package.json`.
- **Build only, nothing published:** `gh workflow run release.yml -f yayinla=false`.
- **Asset names have no version:** `awPDF-linux-amd64.deb`, `awPDF-linux-x86_64.AppImage`, `awPDF-win-x64.exe`, `awPDF-android.apk`.
- **Google Play:** the Android job also builds `awPDF-android.aab` (`bundleRelease`, same key; on Play this key is the app signing key and the upload key, the user's 2026-11-03 decision). It is never attached to the GitHub release: it is the `play-Android` artifact (kept 30 days), downloaded with `gh run download <run> --name play-Android` and uploaded to Play Console by the user.
- **Shared files:** the workflow and `scripts/release-assets.mjs` are identical copies in drAW, drAW2D, drAW3D and awPDF — change all four together. Change release notes in the script, not on GitHub.
- **Trigger quirk:** push a new or changed workflow file before the tag.
- **Google Play listing:** texts and images in `docs/play/` (`magaza.md`); the privacy policy is `public/gizlilik.html`, live at `madematik.com/awPDF/gizlilik.html` and linked from Play. It states that nothing is collected or sent: a change that collects or sends anything (ads, analytics, network) must update it and Play's data safety form.
- **Metadata:** license MIT (same text in all four repos), deb `Section: education`, `.desktop` categories `Office;Viewer;Education`.

## Tests

Playwright specs in `tests/`: `tools.spec.ts` imports `src/` modules directly (page ranges, page plans and PDF writing are checked there with pdf.js in Node); `editing.spec.ts` covers forms, saving (it stands in for `showSaveFilePicker`) and the page editor; `toolbar.spec.ts` covers the row and its menu; `viewer-integration.spec.ts` and `reading.spec.ts` drive the UI through `#pdfInput`. Touch is real: CDP `Input.dispatchTouchEvent` with `hasTouch`. `tests/helpers/make-pdf.mjs` writes real PDFs in memory, so no binary fixtures are committed; `scripts/test-electron.mjs` uses it too. A debug build installs as `com.madematik.awpdf.deneme` ("awPDF Deneme", `android/app/src/debug/res`), beside the Play copy, whose signature it does not share: `npm run build && npx cap sync android` (from the repository root, not `android/`) then `cd android && ./gradlew assembleDebug` and `adb install -r app/build/outputs/apk/debug/app-debug.apk`; its WebView can be inspected over `adb forward tcp:9229 localabstract:webview_devtools_remote_<pid>`. Without a phone: `tests/helpers/android-bridge.ts` stands in for Capacitor's native side, so the Android platform's TypeScript runs in Chromium (`tests/android.spec.ts`); `assembleDebug` checks the Java, which must be tried on a device.

`dist/`, `dist-electron/`, `release/`, `public/pdfjs/` are build outputs and not committed.
